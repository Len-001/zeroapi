# ZeroAPI · 巴别塔协议

**零接口文档的软件自组装总线** —— 把两个从未见过彼此的系统丢进同一个网络，
它们自动识别对方的数据结构、自动合成转换胶水、毫秒级完成业务缝合。

```
系统 B · 遗留仓库管理系统 (2009)              系统 A · 现代 CRM (2026)
  XML  · 拼音缩写 · 分 · Unix秒 · 0/1           JSON · 英文驼峰 · 元 · ISO8601 · boolean
  sp_mc / jg_fen / cjsj / sf_sx                 productName / priceYuan / createdAt / isListed
        │                                                        ▲
        │  ① 信封解码 XML→JS 对象                                 │
        │  ② 嗅探 ADT 图（静态 DDL ⊕ TS 契约 ⊕ 动态流量样本）      │
        │  ③ 神经符号同构求解（语义锚定 + 单位/类型算子链 + 匈牙利算法）
        │  ④ 业务不变量验证（类型域 / 往返恒等 / 货币守恒 / 时间点恒等）
        │  ⑤ 编译成真实可执行的桥接器源码（0 行人手编写）
        └──────────────►  ZeroAPI 巴别塔网关 ◄───────────────────┘
```

| 指标 | 实测值 |
| --- | --- |
| 字段匹配精度（对照人工标注 Ground Truth） | **P = 1.000 / R = 1.000 / F1 = 1.000**（7/7 全中，0 误配 0 漏配） |
| 首次桥接端到端耗时（含嗅探+求解+验证+编译） | **8.6 ms** |
| 缓存命中请求 p50 / p95 | **1.0 ms / 2.0 ms** |
| 结构突变自愈 p50 / p95 / max | **1.34 ms / 1.91 ms / 2.44 ms** |
| 8 轮连续协议突变（改名/改风格/改单位/改类型/加字段/删字段/恶意改名） | **8/8 全部自愈，金额逐轮守恒** |
| 自动生成的桥接器源码 | **55 行 / 3.9 KB，人手编写 0 行** |
| 反向桥接（现代 → 老 ERP） | 199.99 元 → 19999 分，ISO → Unix 秒，老 ERP 行数 4→5 |
| 128×128 字段规模求解 | 138 ms（其中匈牙利算法本体 1.4 ms） |

## 快速开始

```bash
# 需要 Node.js ≥ 18，零第三方依赖，零构建步骤
node bin/start.js
```

启动后打开 **http://127.0.0.1:8310/** —— 这就是演示控制台。

三个独立进程（刻意不用同进程多端口，"跨系统集成"才是真的）：

| 端口 | 系统 | 特征 |
| --- | --- | --- |
| 8312 | `legacy-wms` 系统 B | `text/xml`，字段 `sp_mc`/`jg_fen`，金额单位为**分**，时间是 Unix 秒，布尔是 `0/1` |
| 8311 | `modern-crm` 系统 A | JSON，字段 `productName`/`priceYuan`，金额单位为**元**，时间 ISO 8601，布尔是真 `boolean` |
| 8310 | `zeroapi` 巴别塔网关 | 桥接器 + 演示控制台 + SSE 事件流 |

其它入口：

```bash
node tests/run.js          # 全部测试（核心层 77 + 端到端 13）
node tests/run.js --core   # 只跑核心算法（不起服务）
node tests/run.js --e2e    # 只跑端到端（真实三进程 HTTP）
node bin/start.js --check  # 启动自检后退出（CI 用）
node scripts/smoke.js      # 不起 HTTP 的纯核心链路冒烟
```

## 大屏演示剧本（3 分钟，全程交互）

控制台顶部三颗按钮就是剧本：

1. **① 直连（无 ZeroAPI）** —— 左栏前端收到老 ERP 原始报文，
   `item.priceYuan.toFixed(2)` 当场抛 `TypeError`，列表渲染中断。
   这不是准备好的文案，是页面里**真实抛出**的异常。
2. **② 启动巴别塔网关** —— 中间面板开始绘制拓扑连线：左边是现代字段、右边是拼音字段，
   连线上的彩色胶囊标出自动挂上的算子（`÷100` / `⏱→ISO` / `0/1→✓`）。
   左栏 4 条商品数据全部正常渲染。
3. **③ 全链路同步到 CRM** —— 老 ERP → 网关 → 现代 CRM。
   CRM 做**严格契约校验**（多一个字段、少一个字段、类型不对，一律 422 拒收），
   接收成功即证明"零胶水对齐"是真的。

然后是**破坏性测试**（右栏 8 个按钮）：

- 改字段名 `jg_fen → dj_fen`
- 命名风格整表切换（全拼 / 全大写 / 驼峰）
- 单位 `分 → 元`
- 类型 `int → string`
- 新增字段 `品牌`
- 恶意改名（改成词典无法锚定的乱码）
- 删除字段 `是否上架`
- 收紧契约（把 `brand` 从可选改成必填）

每次破坏后**再点一次 ②/③**，就能看到中间面板在毫秒级重新求解并热替换桥接器，
前端全程零改动。

我们刻意保留了两个**不糊弄**的场景：

- **恶意改名**：字段名和注释同时丢失后，`priceYuan` 直接缺省，
  而不是把 `39999` 当成 39999 元放行 —— 那是一次 100 倍的资金事故。
- **收紧契约**：`brand` 改成必填后，CRM 精确拒收并点名"缺少必填字段 brand"，
  而不是悄悄塞个 `null` 让它几个月后炸在数据库里。

## 架构（三层）

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 第一层 | `src/core/extractor.js`<br>`src/core/lexicon.js` | **无感契约嗅探器**。静态证据（SQL DDL 的中文 COMMENT、TS `interface`）+ 动态证据（真实报文样本）合成代数数据类型图（ADT Graph）。中文语义靠词典锚定 + 拼音音节 DP 切分解决：`sp_mc` → 商品名称、`jg_fen` → 价格（分） |
| 第二层 | `src/core/solver.js`<br>`src/core/operators.js`<br>`src/core/verifier.js` | **神经符号同构搜索引擎**。语义距离 + 算子链代价构成代价矩阵，匈牙利算法求最小代价双射；单位换算/编解码/类型提升被建模成状态空间上的带权图，寻路退化为 Dijkstra。产物必须再通过三层不变量校验（类型域 / 往返恒等 / 业务守恒）才允许上线 |
| 第三层 | `src/core/compiler.js`<br>`src/core/bridge.js` | **热插拔桥接器**。把映射计划编译成**可读的 JavaScript 源码**（大屏上直接展示），带结构指纹做 O(1) 命中判定；结构突变时重求解并热替换，重编译预算 + 形状备忘两道闸门防抖动 |

### 冲突裁决纪律（贯穿全项目）

> **值证据 > 命名线索 > 默认值。冲突不静默吞掉，一律落成 warning 上报。**

### 三层不变量闸门

- **L1 类型域** —— 转换产物必须落在目标声明的类型域内
- **L2 往返恒等** —— 逆链必须复原原值（含 `round` 之类有损算子会被直接拒绝）
- **L3 业务守恒** —— 货币守恒、时间点恒等、布尔域收敛、数量恒等

任何一条不过，该字段对就被**降级为未匹配**并上报原因，绝不带着"看起来能跑"的转换函数上线。

## 已知边界（不吹的部分）

1. **语义词典是符号先验，不是通用理解。** 当前词典覆盖电商/ERP 常见业务概念。
   跨领域时命中率会下降，靠 L3 字面兜底并抬高门槛（宁可拒配，不可错配）。
   词典输出的 `concept/confidence` 可直接作为 LLM 提示词的结构化先验 —— 这是预留的神经侧接入点。
2. **单位翻转若同时不改变量级与小数性，无法从数据侧判定。** 例如 `39900 分 → 399 元`
   （整列都是整数）在缺少声明时不可判定；有实时 schema 声明时由声明兜底。
   这是信息论上的限制，不是实现缺陷 —— 系统在这种情况下的行为是**拒配**而非猜测。
3. **XML 层面没有类型。** `int → string` 这类类型突变在 XML 线上是隐形的
   （数字字符串会被信封解码器还原）。JSON 系协议上才会真正体现。
4. **无认证、无持久化、无分布式一致性。** 这是原型，不是产品。
   桥接器状态在单进程内存里，重启即冷启动。
5. **性能数据来自单机 localhost。** 跨网络、跨机房的时延未测。
